# Переход brevi.com.ua на Next.js: план миграции

**Статус:** план, кода нет. Каждый шаг оформляется отдельным SDD в варианте `nextjs` с обязательным `design/seo.md` (скил `frontend-feature-spec`) и уходит отдельным PR. Слияние только с согласия владельца.
**Дата:** 2026-10-30.
**Связано:** [идея и дизайн «Строчка»](../../../ideas/storefront-nextjs/README.md), [ADR-0001](../../../architecture/site/adr/0001-nextjs-public-site.md), [архитектура сайта](../../../architecture/site/README.md), [SEO-архитектура](../../../architecture/site/platform/seo-architecture.md), [опись страниц и SEO-анализ](feature-inventory.md), [дизайн-система](../../../standards/site/design-system.md).
**Образец:** публичный сайт Кедра, kedr-web `apps/site` и его `docs/specs/site/migration/README.md`.

## Цель

Заменить живой сайт brevi.com.ua (OpenCart) новым сайтом `apps/site` на Next.js App Router, shadcn/ui и Tailwind CSS v4 в дизайне «Строчка».

- Сохранить все проиндексированные адреса и позиции в поиске.
- Исправить SEO-ошибки текущего сайта.
- Привести покупателя к звонку или заявке.

Бизнес: собственный пошив спецодежды с логотипом в Полтаве и продажа СИЗ, в первую очередь оптом. Заказ от 5 штук, три уровня цены (1–9, 10–39, 40+).

Сырая Angular-витрина `apps/storefront` в продакшене не работает. Из неё берём фото, переводы и полезные куски структуры, а сам код не переносим. После переключения домена она удаляется отдельным PR.

## Правила для всех шагов

1. **Адреса живого сайта не меняются:** украинская версия в корне, русская под `/ru/`, свои слаги для каждого языка, слэш как сейчас. Если адрес меняется, добавляется 301 в карту редиректов. См. [SEO-архитектуру](../../../architecture/site/platform/seo-architecture.md).
2. **Новый сайт живёт на превью-домене** с выключенной индексацией до шага 10. Домен до этого обслуживает OpenCart.
3. **Проекты и компоненты создаются командами,** не вручную: `npx nx g @nx/next:application`, `npx nx g @nx/react:library`, `npx shadcn@latest add`. Потом вывод генератора приводится к правилам репозитория. Так проекты видны в графе Nx.
4. **Каждый шаг заканчивается аудитом изменённого кода** (`frontend-code-audit`): большие файлы разбиваются, переполненные папки группируются.
5. **На каждом шаге проверяется SEO:** тесты билдеров, `curl`-проверка HTML (статус, title, description, canonical, hreflang, JSON-LD), строка в таблице URL-политики. Для перенесённых типов страниц проверяется выборка живых адресов.
6. **Данные идут только через `site-shared-api-client`** и доменный `data-access`. Сгенерированные типы не выходят из `data-access`. Цены, тексты и наличие приходят из API.
7. **Тексты, цены и фото даёт владелец или импорт из OpenCart,** код их только выводит.

## Риски

- **Потеря позиций при переезде.** Снижение: те же адреса, полная карта 301 из `seo_url`, hreflang и JSON-LD, которых раньше не было, sitemap, Search Console, переключение только после аудита.
- **Данные остаются в OpenCart.** Если импорт не сделать, сайту нечего показывать. Снижение: шаг 2 начинается сразу, экспорт просим у владельца первым делом.
- **Два источника правды до переключения.** Тексты, правленые в OpenCart после импорта, потеряются. Снижение: заморозить правки контента в OpenCart на время шагов 7–10 или повторить импорт перед переключением.
- **Шаблонные региональные страницы.** Поиск может понизить их как дорвеи. Снижение: уникальный текст или объединение в один набор.
- **Фото товаров.** От них зависит вид минималистичного сайта. Снижение: единый формат фото на белом, заказчик готовит их заранее.
