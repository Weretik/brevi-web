# SDD: список товарів Admin у MUI Data Grid

**Статус:** draft — потребує погодження перед початком розробки  
**Дата:** 2026-07-24  
**Власник домену:** `admin/products`

## 1. Мета

Як менеджер Admin, я хочу переглядати каталог товарів у таблиці, шукати та
відбирати товари тими самими серверними параметрами, що й у storefront-каталозі,
щоб швидко знаходити потрібний товар без завантаження всього каталогу в браузер.

## 2. Контекст і рішення

- Поточна сторінка — `ProductsPage` у `@admin/products/feature`; вона містить
  лише заглушку таблиці.
- Storefront уже використовує параметри `SearchTerm`, `InStock`, `IsSale`,
  `IsNew`, `PriceFrom`, `PriceTo`, `Sort`, `Page`, `PageSize`; Admin отримує
  окремий endpoint з тим самим семантичним контрактом.
- У Admin серверний стан належить RTK Query і має розміщуватись у
  `@admin/products/data-access`; прямі Axios/HTTP-виклики з React-компонентів
  заборонені.
- Таблиця буде реалізована через community-пакет `@mui/x-data-grid`, сумісний з
  наявними `@mui/material` 9.x. Ліцензійні можливості Data Grid Pro/Premium не
  потрібні: серверні pagination, sorting та filter controls підтримуються
  community Data Grid через контрольовані моделі.

## 3. Межі

### У межах задачі

- Реальний запит списку товарів через наявний `@admin/shared/api-client` і RTK
  Query.
- Табличне представлення в `ProductsPage` на MUI Data Grid.
- Серверні пошук, фільтри, сортування й пагінація, еквівалентні storefront.
- Стани завантаження, порожньої відповіді та помилки з можливістю повторити
  запит.
- Встановлення `@mui/x-data-grid` як production dependency без оновлення інших
  залежностей.

### Поза межами задачі

- Створення, редагування, видалення, масові операції, експорт і переходи на
  картку товару.
- Зміна Angular/storefront-коду, авторизації, глобального store та теми Admin.
- Клієнтська фільтрація, завантаження всіх сторінок наперед, кешування поза RTK
  Query.
- Автоматизовані тести — за прямою домовленістю для цієї поставки не додаються.
- Категорії, SKU, залишки або інші поля, яких немає у поточній відповіді API.

### Задіяні бібліотеки

| Бібліотека                    | Відповідальність                                                             |
| ----------------------------- | ---------------------------------------------------------------------------- |
| `@admin/products/feature`     | сторінка, локальний UI-стан параметрів і композиція                          |
| `@admin/products/data-access` | RTK Query endpoint, DTO, валідація й перетворення в доменну модель           |
| `@admin/products/model`       | типи query/рядка та чисті мапери, якщо вони потрібні більш ніж одному модулю |
| `@admin/products/ui`          | domain-presentational таблиця/toolbar без API, router і server state         |
| `@admin/shared/api-client`    | наявний `baseApi` та Axios transport                                         |

## 4. Контракт даних

### Endpoint

```
GET /api/admin/products
```

Endpoint належить Admin API та не залежить від `uk`/`ru` у шляху. Авторизація не
входить до цієї поставки: endpoint доступний за поточними правилами backend.
Локалізація назви товару, якщо вона потрібна в майбутньому, має бути окремим явно
затвердженим параметром або контрактом, а не прихованою частиною URL.

| Параметр API            | Джерело в UI               | Правило                                                                         |
| ----------------------- | -------------------------- | ------------------------------------------------------------------------------- |
| `SearchTerm`            | поле «Пошук»               | trimmed значення; порожній рядок не передавати                                  |
| `InStock`               | перемикач «В наявності»    | `true`/`false`; за замовчуванням `false`, щоб адмін-список показував усі товари |
| `IsSale`                | перемикач «Акція»          | передавати лише при `true`                                                      |
| `IsNew`                 | перемикач «Новинка»        | передавати лише при `true`                                                      |
| `PriceFrom` / `PriceTo` | числові поля ціни          | передавати лише валідні скінченні числа                                         |
| `Sort`                  | сортування Data Grid       | `0..5`, відповідно до таблиці нижче                                             |
| `Page`                  | `paginationModel.page + 1` | API використовує нумерацію з 1                                                  |
| `PageSize`              | `paginationModel.pageSize` | одне з дозволених значень                                                       |

| Поле Data Grid | `Sort` API | Напрям     |
| -------------- | ---------- | ---------- |
| `id`           | `0` / `1`  | asc / desc |
| `name`         | `2` / `3`  | asc / desc |
| `price`        | `4` / `5`  | asc / desc |

Відповідь очікується у вже наявній формі `PagedResult<ProductListRowDto>`:

```ts
type ProductListRowDto = {
  id: number;
  name: string;
  productSlug: string;
  photo: string;
  categoryId: number | null;
  inStock: boolean;
  isSale: boolean;
  isNew: boolean;
  price: number | null;
};
```

`pagedInfo.totalRecords` є єдиним джерелом `rowCount`; `value ?? []` — рядки
поточної сторінки. Некоректна відповідь або `isSuccess: false` має бути
перетворена на типізовану помилку на межі `data-access`, а не показуватися як
порожня таблиця.

## 5. UI та поведінка

### Таблиця

`DataGrid` працює в режимі `paginationMode="server"` і `sortingMode="server"`.
Фільтрацію забезпечує зовнішня toolbar, тому вбудований filter panel/Data Grid
quick filter не використовується, щоб не створити другий, несинхронний набір
параметрів.

| Колонка   | Дані              | Поведінка                                                                           |
| --------- | ----------------- | ----------------------------------------------------------------------------------- |
| Фото      | `photo`           | компактне прев’ю; fallback без зламаного layout, якщо URL відсутній/не завантажився |
| ID        | `id`              | сортується на сервері                                                               |
| Товар     | `name`            | сортується на сервері; повна назва доступна через tooltip за потреби                |
| Ціна      | `price`           | сортується на сервері; `null` відображається як «—»                                 |
| Наявність | `inStock`         | семантичний Chip: «В наявності» / «Під замовлення»                                  |
| Ознаки    | `isSale`, `isNew` | Chip «Акція» і/або «Новинка»; порожня комірка, якщо ознак немає                     |

Початкове сортування — `id asc`. Для запиту з кількома полями sort model
використовується лише перше поле: поточний API підтримує один `Sort`.

### Toolbar фільтрів

1. Поле пошуку має label «Пошук товарів», кнопку «Пошук» і кнопку/обробник
   очищення. Запит виконується лише після натискання Enter або кнопки «Пошук».
   Зміна пошуку повертає до першої сторінки; debounce не використовується.
2. Перемикачі: «В наявності», «Акція», «Новинка». Кожна зміна негайно виконує
   новий серверний запит і повертає до першої сторінки.
3. Поля «Ціна від» і «Ціна до» приймають лише невід’ємні числа. Значення
   застосовуються після явної дії «Застосувати» або Enter. Якщо `від > до`,
   запит не виконується, а користувач отримує доступну текстову помилку.
4. «Скинути фільтри» відновлює admin-значення за замовчуванням:
   `InStock=false`, інші фільтри й пошук порожні, `id asc`, перша сторінка,
   page size не змінюється.

Застосований стан списку (`search`, `inStock`, `isSale`, `isNew`, `priceFrom`,
`priceTo`, `sort`, `page`, `pageSize`) належить `ProductsPage` і зберігається
локально через `useReducer`. Він не синхронізується з URL і не дублюється в
Redux. Невалідні значення нормалізуються до значень за замовчуванням. Чернетка
пошуку та незастосований діапазон цін також лишаються локальним станом toolbar.
RTK Query cache key будується лише з нормалізованого, застосованого query.

### Стани та доступність

- **Loading:** Data Grid показує свій loading overlay, без очищення рядків під
  час refetch поточної вибірки.
- **Empty:** відображає український текст «Товарів за заданими умовами не
  знайдено» та доступну дію «Скинути фільтри».
- **Error:** показує зрозуміле повідомлення без технічних деталей і кнопку
  «Повторити», яка повторює поточний query.
- Інтерактивні елементи мають видимий focus, label/accessible name; статус
  завантаження й помилка оголошуються скрінрідеру за наявним патерном MUI.
- На вузьких екранах toolbar переноситься, а таблиця лишається керованою
  клавіатурою та горизонтально прокручується в межах Card, не розширюючи
  сторінку.

## 6. Сценарії

1. **Початкове завантаження.** Given менеджер відкрив маршрут каталогу, when
   сторінка монтується, then виконується один запит із `InStock=false`,
   `Sort=IdAsc`, `Page=1`, налаштованим `PageSize`; Data Grid показує рядки й
   `totalRecords`.
2. **Пошук.** Given таблиця відкрита, when менеджер натискає Enter або кнопку
   «Пошук», then виконується один запит із trimmed `SearchTerm` і `Page=1`.
3. **Фільтри.** Given менеджер вмикає «Акція» або задає валідний діапазон цін,
   when значення застосовано, then у запиті передаються відповідні параметри та
   таблиця повертається на першу сторінку.
4. **Сортування й пагінація.** Given є кілька сторінок, when менеджер змінює
   sort або сторінку/розмір сторінки Data Grid, then виконується запит із
   перетвореними `Sort`, `Page` і `PageSize`, без клієнтського сортування рядків.
5. **Помилка.** Given API повертає помилку або неуспішну envelope-відповідь,
   when сторінка її отримує, then показується error state, а «Повторити» запитує
   той самий набір параметрів.

## 8. Критерії приймання

- [ ] `ProductsPage` відображає реальні товари з `GET /api/admin/products`
      через RTK Query, без HTTP у компоненті.
- [ ] Таблиця використовує `@mui/x-data-grid` і серверні pagination та sorting.
- [ ] Пошук, `InStock`, `IsSale`, `IsNew`, ціна, sort, page і page size точно
      мапляться на чинний storefront API-контракт.
- [ ] За замовчуванням застосовано `InStock=false`, `id asc`, `Page=1`.
- [ ] Рядок містить лише поля, гарантовані контрактом; ціна `null`, порожнє фото
      та відсутні badges відображаються коректно.
- [ ] Є зрозумілі loading, empty і error стани; retry не змінює активні фільтри.
- [ ] Інтерфейс українською, доступний з клавіатури та не ламає layout на 320 px.
- [ ] Пошук надсилає запит лише після Enter або натискання кнопки «Пошук»;
      діапазон цін — лише після натискання «Застосувати».
- [ ] Не змінено storefront, backend, маршрути, глобальний Redux store чи
      не пов’язані домени.

## 9. Перевірка

Автоматизовані тести не є частиною цієї поставки.

Після реалізації обов’язково виконати:

```text
npm install @mui/x-data-grid@<сумісна з MUI 9 версія>
npx nx lint admin-products-feature
npx nx lint admin-products-data-access
npx nx lint admin-products-ui
npx nx build admin
```

Ручна перевірка: initial/load/refetch/error/empty стани; всі фільтри; пошук за
Enter і кнопкою; застосування ціни кнопкою; сортування; пагінація; 320 px, 768 px, 1200 px; keyboard/focus;
світла й темна схеми.

## 10. Відкриті питання

1. Зафіксувати backend contract для `GET /api/admin/products`: query параметри
   `SearchTerm`, `InStock`, `IsSale`, `IsNew`, `PriceFrom`, `PriceTo`, `Sort`,
   `Page`, `PageSize`; envelope `PagedResult`; відсутність авторизації в цій
   поставці та семантика локалізованої назви товару.
2. Визначити, чи посилання з рядка на майбутню сторінку товару буде окремою
   задачею. У цій поставці рядки не навігують.
