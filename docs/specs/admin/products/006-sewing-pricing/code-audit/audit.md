Topology decision: split UI by calculation/publication/workflow rather than collect nine presentation files in one flat directory. Keep four root files (shell, consumer props, shared tiers, price formatting). Keep the three pricing hooks together: Article read orchestration, Article writes and Product batch projection are cohesive and remain below the eight-file signal. Validation primitives retain one shared boundary-validation role rather than creating a file per predicate.

Backend review: `Catalog.Infrastructure/Pricing/History/Publications/Reading/SewingPublishedPriceReader.cs` owns one bounded read projection: two queries followed by grouping into its read contract. Application validation, authorization, row shape and reader interface already have separate owners. Keep this adapter together; no backend code change or migration is justified by line count. Backend review is static, not fresh runtime verification.
