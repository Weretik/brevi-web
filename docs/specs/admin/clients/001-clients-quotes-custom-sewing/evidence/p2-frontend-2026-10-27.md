## Observable P2 behavior

- Existing quotes menu opens list/new/detail routes. Search/status/page live in URL; list reads remain bounded. Access errors hide list data and prevent create actions until scoped access is known.
- New quote selects existing customer/contact or a named recipient. Saved quotes use the frozen recipient and version actor. Product/Article pickers reuse Catalog APIs, search and paging; inactive articles cannot be selected.
- Items and variants reorder while retaining logical IDs, snapshots and visibility. Public description/comment and internal notes are distinct. Null/blocked prices are never replaced by zero.
- Sewing/PPE selection and reasoned PPE overrides obtain prices from explicit server previews. One-off PPE has its own typed manual basis and reason, without creating a Product. Three semantic tiers are displayed without invented quantity ranges or extra VAT.
- Save creates V1 or appends an immutable version using expectedRevision. Reopen/text edits reuse saved monetary basis; their request body does not present an expired historical token as a fresh preview. Changed intent requires a fresh token.
- 409 leaves local input intact. Reload/discard and navigation are explicit. Unknown write results lock editing and retry the original captured payload/requestId; successful reconciliation unlocks the form. Double submit is guarded synchronously. Late previews cannot overwrite changed selection; explicit refresh after a successful preview uses a new request ID.

## Red → Green → Refactor

`quote-response.unit.test.ts` initially reproduced three behavioral failures: duplicate semantic tiers, variant Article differing from basis, and missing Catalog source were accepted. Runtime mapping now rejects them; the focused mapper tests pass. Detail/item/variant and request-intent mappers are separate files.

`use-quote-editor.unit.test.tsx` reproduced changed payload/requestId after a timeout. Capturing the original pending write fixed that failure; retries bypass local token expiry only to reconcile the same request. A definite conflict releases that capture while preserving the current form. This behavior is also exercised through the real form in the component tests.

The final error review added a failing test for definite HTTP 400 without field-specific errors: it was incorrectly classified as uncertain. Classification now uses the actual outcome: status 0, 408, 5xx or an unnormalized/unreadable response are uncertain; definite client errors allow correction. This regression passes in the final feature run.

The HTTP/cache test fixture initially omitted the summary's versionNumber and was corrected; that failure was fixture setup, not Red evidence. A dialog test initially queried the underlying form during MUI's exit transition; waiting for the accessible form fixed the test timing.
