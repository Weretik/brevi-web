# Пропозиція для першого знайомства

Спільні backend правила R-I01–03, сценарії SC-I01–03. Джерело v211 має окремі сезонні добірки й власні збережені шаблони менеджера; це не лише текст вступу.

- **R-I01:** Формати «Загальний» (літо+зима, 8 моделей), «Літній» і «Зимовий» (4 моделі). На сезон — одна явно налаштована головна модель й три інші різні моделі; одна тканина/артикул на слот. Валідувати сезон, склад/щільність тканини, товарне посилання Brevi та доступну позитивну ціну великого опту. Source головні моделі «Імпульс»/«Прайм» прив'язуються backend через явну versioned identity конфігурацію, не regex/hardcode IDs у UI.
- **R-I02:** Manager створює, називає/редагує, архівує й повторно використовує **власні** selection templates; Admin керує всіма. Це не Admin-only налаштування юридичного продавця/макета. Шаблон зберігає формат/слоти/вибір товару й тканини/email template reference, а не стару актуальну ціну. Повторне застосування створює нову чернетку з поточним серверним розрахунком; заміна відсутніх selections явна.
- **R-I03:** Результат є presentation kind звичайного КП, із закріпленою версією/PDF/outbox. Повторний перегляд виданої добірки незмінний; нова добірка з шаблону бере поточні approved входи. Одне/два сезонні представлення не створюють іншу БД/модуль надсилання.

| Сценарій | Given / When / Then                                                                                                                                              |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SC-I01   | Є approved models/featured mappings → обирає формат і тканини → 4/8 правильних слотів, без сезонних дублів, з metadata/URL/large-tier; конкретні blockers видимі |
| SC-I02   | Власний шаблон та нові ціни → редагує/архівує/застосовує → нова чернетка має current server price, старий PDF незмінний; чужий ID недоступний                    |
| SC-I03   | Готова добірка та явний одержувач → генерує PDF/надсилає → правильні сезонні сторінки/ціни, жодних costs/private notes, звичайна pinned delivery history         |

Порожній список шаблонів, втрачені featured mappings/тканини, ціна blocked, pending preview/save/conflict — окремі стани. Не виконувати автоматичне надсилання при виборі шаблону. Навігація з «Розрахунки та КП», без нового дубля пункту клієнтів.

## P6 email-version prerequisite — 2026-11-01

SC-I01–02: нова добірка зберігається лише з реальною явно обраною версією листа. Пагінація не змінює вибір. Історична добірка зберігає старе посилання до явної заміни; активна версія не підставляється автоматично. Завантаження/порожній/помилковий реєстр блокують нові посилання та дають retry; відмова доступу очищає приватний стан. [Дизайн](../design/p6-delivery-production.md).
