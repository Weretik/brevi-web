# Редактор КП та історія

Спільні правила R-Q01–09, сценарії SC-Q01–07.

- **R-Q01:** Окремо показувати draft/ready/sent, поточну та видану версії, номер і автора. Після редагування виданої версії створюється нова чернетка. Архів — окрема ознака.
- **R-Q02:** Обирати швейний артикул Catalog або СІЗ, приватну custom version чи разові СІЗ. Позиції й альтернативи мають зрозумілий порядок, назви/опис/коментар/фото та прапорці для клієнта/PDF; приватні нотатки явно відділені.
- **R-Q03:** Три семантичні рівні цін мають окремі прапорці показу. Діапазони кількості й валюта беруться з контракту, не hardcode з legacy назв. Поля норм компонентів не є обов'язковою кількістю замовлення. Недоступна ціна показує причину, не «0».
- **R-Q04:** Браузер надсилає намір/вибір/норми, отримує серверний розрахунок та basis token. Не рахує підсумкові ціни своїм рушієм і не підставляє deprecated Product.Price.
- **R-Q05:** Перегляд, зміна тексту, копіювання або PDF не перераховують автоматично. «Перерахувати» показує стару/нову ціну, змінені джерела й підтвердження нової версії. Скасування лишає попередню. Прострочений basis/409 не виправляти автоматичним перезаписом.
- **R-Q06:** Ручна ціна лише СІЗ із позитивною сумою/рівнем/причиною. Для пошиття редагуються дозволені норми, не фінальні ціни. Разові СІЗ мають окрему ручну основу й не створюють товар.
- **R-Q07–08:** Пошук/фільтри, історія, копія, передача й архів виконуються за серверними capabilities. Передача показує нового відповідального і втрату доступу; копія не переносить номер/надісланість. Історію не підміняти живими довідниками.
- **R-Q09:** Заблоковані 724/931 не обходити через UI; 452/453 використовують звичайний серверний склад із підтвердженою операцією.

| Сценарій | Given / When / Then у UI                                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| SC-Q01   | Клієнт і товари доступні → додає/переставляє позиції/варіанти, зберігає → reload відновлює порядок, текст, три ціни й видимість                  |
| SC-Q02   | V1 збережена, входи змінились → відкриває/редагує текст, потім явно перераховує → стара ціна збережена до підтвердження V2                       |
| SC-Q03   | СІЗ і пошиття → вводить override → причина обов'язкова лише у дозволеному ручному сценарії; sewing total не редагується                          |
| SC-Q04   | Інший редактор уже зберіг → отримує 409 → бачить reload/порівняння, введення не губиться, автоматичного overwrite немає                          |
| SC-Q05   | Доступне КП → копіює/передає/архівує/відновлює → стани/власник/історія відповідають дії й новій області доступу                                  |
| SC-Q06   | Разові СІЗ чи legacy individual → відкриває/створює допустимий запис → typed content або чесний read-only/incomplete стан, без вигаданого товару |
| SC-Q07   | Немає ціни/активності або все приховано → готує КП → бачить конкретний blocker і не отримує псевдоціну/готовий документ                          |

Стан редактора: loading/empty draft/success/error/forbidden/not-found, dirty/calculating/preview-ready/saving/saved/conflict/blocked. Під час запису блокувати повторний submit, зберігати той самий requestId для повтору невизначеного запиту, не для нового payload. Після явної зміни входів старий preview позначити непридатним. Попередження про вихід лише для незбережених змін; не губити введення через перевірку доступу або мережеву помилку.
