# Клієнти та контакти

Спільні backend правила: R-C01–06, сценарії SC-C01–05.

- **R-C01:** Відкривати наявний пункт «Клієнти», один список і одну картку; не створювати додатковий довідник/меню.
- **R-C02:** Форма підтримує організацію/особу, назву, застосовні юридичні дані, контакти/канали, відповідального, стан. Не вимагати IBAN/ЄДРПОУ для кожної особи. Користувач не є обліковим записом Identity.
- **R-C03:** Контакти мають ім'я/посаду/email/телефон/основний стан. Зберігати введений номер, не обмежувати міжнародний формат місцевою маскою. Показувати серверну перевірку основного контакту й неактивності.
- **R-C04:** Схожі назви/телефони — кандидати, не автозлиття. Admin має явний перегляд злиття з вибором survivor, підтвердженням двох revision та поясненням, що історичні КП не зміняться. Конфлікт source identity показувати без тихого перезапису.
- **R-C05:** Деактивація не видаляє історію; неактивного клієнта/контакт не пропонувати для нового готового КП. Історична версія показує зафіксовані дані, а не поточну картку.
- **R-C06:** Admin бачить усе; Manager — своїх клієнтів і клієнтів поточно призначених йому КП, змінює лише власний master; User не отримує CRM за замовчуванням. UI guards доповнюють серверну авторизацію.

| Сценарій | Given / When / Then у UI                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| SC-C01   | Менеджер відкрив наявних «Клієнтів» → створив клієнта/контакт → запис відкривається після reload у тій самій картці                   |
| SC-C02   | Є схожа назва/source identity → створює кандидата → бачить варіанти перевірки або точний конфлікт, без дубля/автозлиття               |
| SC-C03   | Контакт використано у V1 → змінює основного/деактивує → поточна картка оновлюється, одержувач V1 незмінний                            |
| SC-C04   | Чужий ID або недостатня роль → відкриває/редагує → доступ обмежений, дані та чужі підрахунки не витікають                             |
| SC-C05   | Admin підтвердив два дублікати → зливає → live-посилання ведуть на survivor, історичні назви збережені; stale revision вимагає reload |

Для списку: loading/success/empty/error/forbidden, bounded search, фільтр активності, пагінація з backend total. Для картки: validation, pending save, success, conflict, not-found/forbidden; збереження без повторного submit, блокування втрати незбережених змін. Клавіатурний доступ, фокус після діалогу та повідомлення українською.
