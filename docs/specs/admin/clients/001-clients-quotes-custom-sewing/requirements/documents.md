# Готовність, PDF та надсилання

Спільні правила R-D01–06, сценарії SC-D01–04.

- Admin редагує/активує версійні реквізити **продавця** й шаблон. Дані форми «Настройки КП» не є банківськими даними клієнта. Непідтверджені реквізити/податкова політика/нумерація блокують ready/PDF, але не збереження чернетки.
- Перед ready показати перевірку одержувача, видимих варіантів/цін, джерел і реквізитів. Номер видає сервер за погодженою політикою, frontend не генерує свій.
- Перегляд/скачування PDF працює із збереженим приватним артефактом конкретної quote version. Стани queued/rendering/ready/failed/missing не підміняти порожньою сторінкою або success. Скачування не змінює sent.
- Надсилання — окрема явна дія: вибрана версія/PDF, показаний одержувач і підтвердження. queued/processing/succeeded/failed/unknown показуються за backend, успіх тільки після підтвердження провайдера. unknown не пропонує сліпий автоматичний повтор із новим ключем.
- При зміні живих реквізитів/клієнта збережений PDF і видана версія незмінні. Приватні нотатки, собівартість, приховані ціни/варіанти, override reasons і production-only файли виключає сервер. UI не створює клієнтський документ із внутрішнього DTO.

| Сценарій | Given / When / Then                                                                                                               |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| SC-D01   | Чернетка без перевірених реквізитів → зберігає/готує → save працює, ready пояснює конкретний blocker                              |
| SC-D02   | Ready версія з прихованими даними → генерує/скачує після зміни master → PDF відповідає виданій версії, приватного вмісту немає    |
| SC-D03   | Користувач явно обрав одержувача → надсилає/повторює невизначений запит → одна delivery, правдивий стан, історія саме цієї версії |
| SC-D04   | Пошкоджений/чужий файл чи небезпечний текст → рендер/скачування → безпечна помилка, раніше готовий артефакт не губиться           |

Потрібні доступні назви кнопок, повернення фокусу після діалогу, оголошення стану обробки, читабельність вузького/широкого екрана. Службові транспортні подробиці й секрети не показувати. Повторне надсилання як нова бізнес-дія потребує окремої явної дії/нового requestId, а не мережевого retry.

## P6 реєстр шаблонів — SC-D03 prerequisite

Admin переглядає незмінні версії теми/звичайного тексту листа, створює нову версію й окремо підтверджує активацію. Manager має лише перегляд. Створення не змінює активну версію й не надсилає лист. Конфлікт активації потребує поточної revision, невідомий результат зберігає той самий запит, втрата доступу приховує приватний стан. [Дизайн](../design/p6-delivery-production.md).
