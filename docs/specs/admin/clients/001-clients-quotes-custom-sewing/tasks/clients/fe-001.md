# FE-001 — Межа даних клієнтів

**Стан:** client slice implemented / automated checks verified; manual acceptance pending. **Covers:** SC-C01–05. **Depends on:** FE-EN-001, FE-EN-002 для backend TS-002.

## Шляхи та відповідальність

Заплановані області: `libs/admin/clients/data-access/src/customers/{api,mappers,validation}/; model/src/customers/; core permissions public API`. У скорочених шляхах `feature/`, `ui/`, `model/`, `data-access/` базою є `libs/admin/clients/`. Один компонент/hook/mapper/type — одна основна відповідальність і окремий файл; grouping за сценарієм, public exports через index.ts.

## Робота

Додати операційні RTK Query endpoints, runtime validation/mapper, pure customer/contact models, scope capabilities, list pagination і requestId/revision errors. Не дублювати generated DTO та не зливати mapper/validator/transport в один великий файл.

## Test level та Evidence

Focused mapper/query error tests: total metadata, shared email, source conflict, 401/403/404/409/422, stable retry key і precise invalidation.

Перевірити існування project targets перед запуском. Для нової поведінки записати focused Red → Green → Refactor → Regression (test name/команда/результат); для discovery/документації — source/link/diff evidence. Evidence зараз **не виконано**. Під час реалізації додати датований `evidence/fe-001.md` у SDD із SHA контракту, зміненими файлами, перевірками та обмеженнями.

## Checkpoint

Feature отримує domain models і безпечні помилки, не wire DTO/довільні HTTP виклики.

Невирішений prerequisite блокує лише залежний slice; не підміняти його mock API як реалізованою можливістю. [План](../implementation-plan.md).
