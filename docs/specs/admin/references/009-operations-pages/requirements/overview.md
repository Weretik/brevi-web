# Операції — правила та приймальні сценарії

## Мета та межі

- **Актор:** співробітник Admin.
- **Мета:** керувати елементами виробу й роботами через таблиці та MUI Drawer
  для перегляду, створення й редагування.
- **У межах:** дві вкладки, контекстні дії, українська locale, Drawer,
  семантичні білі фрейми, наявна validation і delete confirmation.
- **Поза межами:** нові поля, зміна одиниць часу, нові зв'язки, масові business
  operations, нові дизайн-токени або версії MUI.

## Бізнес-правила

- **R-001:** `/references/garment-part-operation` зберігає вкладки «Елементи» й
  «Роботи»; активна вкладка кодується в URL query та відновлюється після back/reload.
- **R-002:** Обидві таблиці не мають колонки «Дії». Правий клік відкриває для
  конкретного рядка «Перегляд», «Змінити», «Видалити»; delete потребує
  підтвердження й не змінює selection без наміру користувача.
- **R-003:** Те саме меню доступне на сфокусованому рядку через Context Menu key
  або Shift+F10, закривається стандартно й повертає фокус.
- **R-004:** Усі системні тексти Data Grid обох вкладок українські через
  централізовану MUI locale, включно з menus, pagination, filter/no-results.
- **R-005:** Create/view/edit відкривають правий MUI Drawer поверх відповідної
  вкладки без переходу на неіснуючий child URL і без втрати стану списку.
- **R-006:** View mode є read-only, показує чинні поля в білих семантичних
  MUI Paper; кнопка «Редагувати» перемикає той самий Drawer у edit mode.
- **R-007:** Create/edit кожної сутності використовують одну структуру форми:
  create порожній/unselected, edit заповнений. Робота зберігає обов'язковий
  вибір елемента, назву й невід'ємні хвилини.
- **R-008:** Усі поля лежать у білих фреймах. За кількох логічних груп вони
  розділяються горизонтально або вертикально; вузький viewport складає їх в
  одну колонку. Невелика форма елемента може мати одну цілісну білу Card.
- **R-009:** Використовуються готові MUI Material/Data Grid components і тема
  Brevi; screenshots задають layout, не нові дані.

## Приймальні сценарії

### SC-001 — Стабільна вкладка

**Охоплює:** R-001

- **За умови** співробітник відкрив одну з двох вкладок
- **Коли** переходить до запису, повертається або reload сторінку
- **Тоді** активна вкладка й таблиця відновлюються з URL.

### SC-002 — Меню рядка

**Охоплює:** R-002, R-003

- **За умови** у таблиці елементів або робіт є сфокусований рядок
- **Коли** співробітник викликає його меню мишею чи клавіатурою
- **Тоді** бачить три дії правильного запису без колонки «Дії», а закриття
  зберігає коректний фокус і selection.

### SC-003 — Український інтерфейс таблиці

**Охоплює:** R-004

- **За умови** системний control Data Grid доступний
- **Коли** співробітник відкриває його в кожній вкладці
- **Тоді** підписи й повідомлення українські.

### SC-004 — Перегляд у Drawer

**Охоплює:** R-005, R-006

- **За умови** елемент або робота існує
- **Коли** співробітник обирає «Перегляд» у меню рядка
- **Тоді** бачить read-only дані у правому Drawer та кнопку редагування, а URL
  вкладки не змінюється.

### SC-005 — Спільний create/edit Drawer

**Охоплює:** R-007, R-008

- **За умови** створюється або редагується елемент чи робота
- **Коли** відкривається Drawer
- **Тоді** create порожній, edit заповнений, структура одного типу однакова,
  поля згруповані в адаптивних білих фреймах.

### SC-006 — Lookup і збереження роботи

**Охоплює:** R-007

- **За умови** форма роботи завантажує список елементів
- **Коли** lookup успішний або недоступний і співробітник намагається зберегти
- **Тоді** валідний вибір зберігається, а помилка lookup/write лишає форму й
  введене доступними для виправлення або повтору.

### SC-007 — Видалення

**Охоплює:** R-002

- **За умови** вибрана дія видалення елемента або роботи
- **Коли** співробітник підтверджує чи скасовує
- **Тоді** список оновлюється лише після успішного підтвердженого delete.

### SC-008 — Адаптивна композиція

**Охоплює:** R-008, R-009

- **За умови** Drawer має одну чи кілька груп даних
- **Коли** змінюється ширина viewport
- **Тоді** кожна група лишається на білій поверхні без втрати полів і overflow.
