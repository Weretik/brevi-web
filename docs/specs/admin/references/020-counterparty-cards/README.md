# 020. Client and supplier cards («Огляд і вкладки»)

**Status:** implemented 2026-11-27. Backend part: BreviERP [CARD-001](https://github.com/Weretik/BreviERP/blob/master/docs/sdd/specs/crm/008-counterparty-cards/README.md). The owner chose concept Б «Огляд і вкладки» on 2026-11-27 from the [concept page](https://claude.ai/artifact/VWCfNehMV2zJLXma4ifRPR).

## Problem

The client card was a bare page: a misplaced «До списку клієнтів» text button, a 1100 px column with empty space on the right, a «Картка» tab with the form inline, and a «КП» tab that loaded forever (it sent `Number(publicId)` = `NaN` as `customerId`, the API answered 400 and the request repeated). The supplier opened in a different drawer with greyed read-only fields. The КП editor never linked the chosen client, so new КП never reached any card. A supplier name opened the nice read-only panel only in КП, fabrics, accessories, price import and the PPE card.

## Decisions

| ID   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | Client and supplier cards are the same page: back link «Контрагенти · …», overline, `h1` name, a line of facts, actions on the right (`CardPageHeader`), one period for every tab (`CardPeriodFilter`, kept in `?period=&from=&to=`), tabs in `?tab=`, full width.                                                                                                                                                                                                                    |
| D-02 | «Огляд» is the first tab: a metric strip with the period counts of every linked list (a cell opens its tab), then data cards (`CardSection`). Client: «Останні КП», «Реквізити», «Контакти». Supplier: «Що закуповуємо» (with notes), «Контакти».                                                                                                                                                                                                                                     |
| D-03 | Client tabs: «КП», «Завдання в цех», «Завдання менеджерам», «Розрахунки вишивки», «Фінанси». Supplier tabs: «Тканини», «Фурнітура», «Товари», «Прихід на склад», «Рахунки на закупку», «Фінанси». Every server list loads one page of 20 rows; the warehouse journal keeps its server page of 50.                                                                                                                                                                                     |
| D-04 | The period applies to КП (created), production orders (order date), tasks and embroidery calculations (created), receipts (operation date) and purchase invoices (document date). «Тканини», «Фурнітура», «Товари» show the reference as it is now; «Фінанси» keeps its own period.                                                                                                                                                                                                   |
| D-05 | Each tab follows the «Права доступу» page of its list (`CustomerCardAccess`, `SupplierCardAccess` from the app slot `use-counterparty-card-access.ts`); a forbidden tab is hidden even from a link. The card itself is the «Контрагенти» page; no new access page.                                                                                                                                                                                                                    |
| D-06 | Editing stays in the side panel: «Редагувати» opens `CustomerEditDrawer` (client) or the existing `SupplierDrawer` in edit mode. Contacts and «Об’єднати з дублем» stay on the client card. «Оновити дані із сервера» is gone: the card refreshes after every save.                                                                                                                                                                                                                   |
| D-07 | The КП editor field «Клієнт або запит» stores `customerPublicId` when a client is chosen and clears it when the name is typed again; «Нове КП» and «Нова КП» on the client card pass it in the prefill.                                                                                                                                                                                                                                                                               |
| D-08 | A supplier name anywhere opens the same read-only panel `SupplierViewPanel` with «Відкрити картку» (was «Відкрити в контрагентах»). The app gives every page one opener (`SupplierCardProvider`, `SupplierCardSlot`); `SupplierName` and `ReferenceDetailsList` `onOpen` use it in «Рух тканини», «Рахунки на закупку» and their side panels. A row of «Постачальники» opens the card page `/references/counterparties/suppliers/:id`; the old `?supplier=<id>` link redirects there. |

## Known limits

- Accessories keep only the supplier name, so they match by name; fabrics match by link or name.
- Warehouse receipts typed with another spelling of the supplier are not found.
- КП of a merged client stay with the removed client; leads have no client link yet.
- A client name is not yet a link outside the card (orders and tasks show text).
