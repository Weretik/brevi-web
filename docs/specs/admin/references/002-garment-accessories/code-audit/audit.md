## Повторний аудит після delivery checkpoint

- `garment-accessories.api.ts` раніше містив і transport, і незалежний розбір HTTP-помилок. Розділення локальне для garment data-access. Не узагальнювали з suppliers transport: це змінило б сторонню feature та її public API.
- `use-garment-accessory-editor.ts` раніше дублював abort/retry логіку supplier lookup. Наявний `useSuppliers` є власником цих станів, тому editor тепер споживає його результат.
- `garment-accessories-grid.tsx` залишено цілісним: визначення колонок, форматування ціни та row action callbacks належать одному представленню. `garment-accessories-page.tsx` лише компонує стан, toolbar, grid і діалоги; окремий модуль для нього не додавався.
- `garment-accessories.mapper.ts` залишено цілісним: runtime перевірка й перетворення одного GET payload утворюють одну boundary. `use-garment-accessory-deletion.ts` тримає вибір разом із підтвердженням, бо обидва стани визначають один delete flow.
- `tools/contracts/contracts.mjs` не розділяли: sync/generate/check є спільним уже наявним pipeline; feature додала тільки перевірку своїх operationId. Angular page/facade/dialog та suppliers feature поза змінами цього аудиту, крім повторного використання `useSuppliers`.
- Перевірка після розділення: `npx nx test admin-references-data-access -- garment-accessories` — 6 passed; `npx nx test admin-references-feature -- garment-accessories-page.component.test.tsx` — 5 passed.
