# Медіа/Фото — правила та приймальні сценарії

## Мета та межі

- **Актор:** співробітник Admin, який керує фотографіями каталогу.
- **Мета:** знайти, переглянути, додати або безпечно видалити фотографію в
  одному розділі React Admin.
- **У межах:** новий пункт меню «Медіа/Фото», прямий URL, адаптивна галерея,
  локальний пошук за назвою файлу, стани завантаження/порожньо/помилка,
  завантаження одного фото, оновлення списку, видалення одного фото з
  підтвердженням та обробка конфлікту використання.
- **Поза межами:** редагування або заміна файлу, alt-текст і прив'язка до товару,
  папки/теги, зміна порядку, масове завантаження чи видалення, оптимізація й
  трансформація зображень, відновлення видаленого, нова модель ролей та зміни
  Angular Admin.

## Бізнес-правила

- **R-001:** «Загальні довідники» містять один пункт «Медіа/Фото»; він відкриває
  `/references/media`, а пряме посилання відновлює ту саму сторінку в Brevi shell.
- **R-002:** Галерея показує кожен валідний запис окремою карткою з прев'ю або
  зрозумілим fallback, оригінальною назвою та станом обробки; внутрішній
  `storageKey` користувачу не показується.
- **R-003:** Завантаження, порожній результат, помилка читання й повтор запиту є
  окремими видимими станами; помилка не прибирає останній успішний список.
- **R-004:** Пошук без урахування регістру фільтрує вже завантажену галерею за
  оригінальною назвою; відсутність збігів не прирівнюється до порожньої
  медіатеки, а очищення пошуку повертає всі картки.
- **R-005:** Додавання приймає один файл лише з погодженими backend MIME і
  розміром; клієнтська перевірка дає ранній зворотний зв'язок, але сервер
  залишається джерелом істини.
- **R-006:** Під час завантаження повторний submit недоступний; успіх оновлює
  галерею й повідомляє результат, а помилка зберігає сторінку придатною до
  повторної спроби.
- **R-007:** Видалення завжди потребує явного підтвердження з назвою фото;
  скасування й помилка залишають фото в галереї, успіх прибирає його після
  підтвердження сервером.
- **R-008:** Фото, на яке посилається товар або інша сутність, не видаляється;
  конфлікт показує зрозуміле повідомлення без втрати картки.
- **R-009:** Картки, пошук, завантаження, повтор запиту й підтвердження видалення
  доступні з клавіатури, мають доступні назви та передбачуваний фокус.
- **R-010:** Frontend не повідомляє про успішну дію після 401/403. Захист самих
  endpoint залежить від спільної Admin-авторизації, якої React Admin і поточні
  catalog/reference controllers ще не мають.

## Приймальні сценарії

### SC-001 — Відкриття галереї

**Охоплює:** R-001, R-002, R-003, R-009

- **За умови** співробітник має доступ до React Admin
- **Коли** він обирає «Медіа/Фото» або відкриває `/references/media` напряму
- **Тоді** він бачить Brevi shell і галерею фото з назвою та станом кожного
  запису, або окремий порожній стан

### SC-002 — Помилка списку та повтор

**Охоплює:** R-003

- **За умови** галерея раніше завантажилася або ще не має успішного результату
- **Коли** запит списку завершується помилкою, а співробітник запускає повтор
- **Тоді** він бачить повідомлення про помилку, останні успішні картки не
  зникають, а повторний запит показує актуальний результат

### SC-003 — Пошук фото

**Охоплює:** R-004, R-009

- **За умови** галерея містить фото з різними назвами
- **Коли** співробітник вводить частину назви з іншим регістром
- **Тоді** залишаються відповідні картки або повідомлення про відсутність
  збігів, а очищення поля повертає всю галерею

### SC-004 — Успішне завантаження

**Охоплює:** R-005, R-006, R-009, R-010

- **За умови** співробітник може керувати медіа й обрав допустиме фото
- **Коли** він запускає завантаження та сервер його приймає
- **Тоді** повторний запуск заблокований до завершення, галерея оновлюється й
  показує нове фото або його поточний стан обробки та повідомлення про успіх

### SC-005 — Відхилене завантаження

**Охоплює:** R-005, R-006

- **За умови** співробітник обрав непідтримуваний файл або сервер відхилив фото
- **Коли** він намагається завантажити файл
- **Тоді** він бачить причину, наявні картки не змінюються й можна обрати інший
  файл або повторити спробу

### SC-006 — Успішне або скасоване видалення

**Охоплює:** R-007, R-009, R-010

- **За умови** галерея містить фото, яке дозволено видалити
- **Коли** співробітник відкриває підтвердження та скасовує його або підтверджує
- **Тоді** скасування залишає фото без змін, а підтверджений сервером успіх
  прибирає фото, показує повідомлення й повертає фокус у зрозуміле місце

### SC-007 — Фото використовується

**Охоплює:** R-007, R-008

- **За умови** на фото посилається товар або інша сутність
- **Коли** співробітник підтверджує його видалення
- **Тоді** фото залишається в галереї, а співробітник бачить, що спочатку треба
  прибрати використання

### SC-008 — Доступ відхилено

**Охоплює:** R-010

- **За умови** сесія відсутня або співробітник не має потрібного доступу
- **Коли** він відкриває сторінку чи виконує дію керування медіа
- **Тоді** застосунок виконує погоджену поведінку для 401/403 і не повідомляє
  про успішну зміну
