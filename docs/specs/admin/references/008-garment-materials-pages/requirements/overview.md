# Тканина та фурнітура — правила та приймальні сценарії

## Мета та межі

- **Актор:** співробітник Admin.
- **Мета:** керувати фурнітурою й тканинами з однієї сторінки вкладок через
  контекстні дії та праві MUI Drawer.
- **У межах:** обидві таблиці, row context menu, українська locale, Drawer,
  read-only view, спільна структура create/edit, MUI Paper.
- **Поза межами:** нові поля, зміна ціноутворення, масове видалення, нові
  дизайн-токени, версії залежностей та інші довідники.

## Бізнес-правила

- **R-001:** Сторінка `/references/garment-accessory` зберігає дві вкладки;
  активна вкладка відновлюється з URL query, щоб повернення зі сторінки запису
  не змінювало контекст.
- **R-002:** В обох таблицях немає колонки «Дії». Правий клік по рядку відкриває
  MUI Menu «Перегляд», «Змінити», «Видалити» для цього рядка; delete лишається
  з підтвердженням, а selection не змінюється побічно.
- **R-003:** Сфокусований рядок відкриває те саме меню через Context Menu key або
  Shift+F10; Escape/click-away/action закривають його з коректним фокусом.
- **R-004:** Усі доступні системні написи обох Data Grid українські через
  централізовану MUI/MUI X locale; feature-specific empty text лишається
  українським.
- **R-005:** Create/view/edit відкривають правий MUI Drawer поверх активної
  вкладки без зміни URL або selection таблиці.
- **R-006:** View mode показує ID, назву, постачальника й ціну в логічних білих
  секціях; «Редагувати» перемикає той самий Drawer в edit mode.
- **R-007:** Для кожного типу запису create й edit використовують одну структуру
  форми й validation: create має порожні/unselected поля, edit — поточні дані;
  первинна дія називається «Створити» або «Зберегти зміни».
- **R-008:** Усі поля лежать у білих MUI Card/Paper. За достатнього обсягу
  основні дані й ціна/постачальник розділяються на окремі семантичні фрейми;
  горизонтальна композиція на широкому екрані стає вертикальною на вузькому.
- **R-009:** Використовуються встановлені MUI Material і community Data Grid;
  референси задають композицію, але не додають полів чи бізнес-дій.

## Приймальні сценарії

### SC-001 — Вкладки й повернення

**Охоплює:** R-001

- **За умови** співробітник працює у вкладці тканин або фурнітури
- **Коли** відкриває запис і повертається до списку
- **Тоді** бачить ту саму вкладку й актуальну таблицю.

### SC-002 — Контекстні дії двох таблиць

**Охоплює:** R-002, R-003

- **За умови** в активній таблиці є рядок
- **Коли** співробітник викликає меню мишею або клавіатурою
- **Тоді** бачить три дії саме цього рядка без колонки «Дії» та може закрити
  меню зі збереженням фокуса й selection.

### SC-003 — Український Data Grid

**Охоплює:** R-004

- **За умови** доступні пагінація, меню колонок, фільтр або порожній стан
- **Коли** співробітник взаємодіє з кожною вкладкою
- **Тоді** всі системні тексти відображаються українською.

### SC-004 — Read-only Drawer

**Охоплює:** R-005, R-006

- **За умови** запис існує
- **Коли** співробітник обирає «Перегляд» у контекстному меню рядка
- **Тоді** бачить дані лише для читання в правому Drawer і кнопку редагування,
  а URL активної вкладки не змінюється.

### SC-005 — Спільна create/edit форма

**Охоплює:** R-007, R-008

- **За умови** співробітник створює або змінює тканину чи фурнітуру
- **Коли** відкривається відповідний Drawer
- **Тоді** структура для одного типу однакова, create порожній, edit заповнений,
  а всі поля містяться у логічних білих фреймах.

### SC-006 — Збереження й помилки

**Охоплює:** R-005, R-007

- **За умови** форма коректна або API повертає field/not-found/conflict error
- **Коли** співробітник зберігає
- **Тоді** успіх оновлює активний список, а помилка не стирає введене й
  дозволяє виправити або повторити дію без подвійного write.

### SC-007 — Видалення

**Охоплює:** R-002

- **За умови** вибрано «Видалити» у меню рядка
- **Коли** співробітник підтверджує або скасовує дію
- **Тоді** підтвердження оновлює активний список, а скасування нічого не змінює.

### SC-008 — Адаптивні білі поверхні

**Охоплює:** R-008, R-009

- **За умови** Drawer відкритий на підтриманій ширині
- **Коли** viewport змінюється
- **Тоді** секції не зливаються з фоном, не гублять поля й переходять до
  вертикальної композиції на вузькому екрані.
