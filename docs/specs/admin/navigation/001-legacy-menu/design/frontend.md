# Меню та шапка — проєктування frontend

## Наявний контекст

- Джерело назв і порядку: `libs/admin/shell/src/lib/layout/sidebar/sidebar.ts`; чотири Angular-маршрути: `libs/admin/feature/references/src/lib/lib.routes.ts`.
- React: `apps/admin-react/src/app/router/app-router.tsx` має тільки `/` та fallback; `libs/admin/core/shell/src/navigation/` малює плоский список, `components/admin-top-bar.tsx` — чинну шапку.
- Інструменти: `admin-core-shell` і `admin-react` мають lint/typecheck/test; `admin-react` — build; `admin-react-e2e` — Playwright.
- Візуальні референси від користувача: [бічна панель](../../../assets/visual-references/admin-sidebar.png), [вкладене меню](../../../assets/visual-references/products-submenu.png) і [верхня панель](../../../assets/visual-references/admin-top-bar.png). Це приклади композиції, а не джерело бренду, контенту чи функцій: залишаються кольори/логотип Brevi та українські підписи.

Після звірки з референсами бічна панель використовує темну поверхню Brevi,
логотип для темного тла, статичний блок робочого простору, вкладені групи з
вертикальною лінією та помаранчевий стан активного посилання. Шапка лишається
компактною і показує тільки назву та дієві кнопки меню й теми. Пошук, аватар,
сповіщення і мови з референсу не додаються без окремої feature.

## Карта пунктів

| Група              | Пункти в початковому порядку                                                               | React-активація                               |
| ------------------ | ------------------------------------------------------------------------------------------ | --------------------------------------------- |
| Менеджер сервісу   | Клієнти; Ліди; Постачальники; Розрахунки та КП; Прайс; Архів КП; Завдання в роботу; Угоди  | немає реалізованих маршрутів                  |
| Швейний цех        | Графік роботи; Зарплата; Тканина в цеху; Фурнітура в цеху; Робочий час; Вишивка; Каса цеху | немає                                         |
| Бухгалтерія        | Рахунки; Надходження; Витрати; Звіти; Довідники                                            | немає                                         |
| Загальні довідники | Товари; Тканина та фурнітура; Операції; Постачальники; Розрахунки; Додаткові довідники     | тільки разом із відповідними React-сторінками |
| Загальні звіти     | окремий пункт                                                                              | немає                                         |

«Постачальники» менеджера сервісу й «Постачальники» загальних довідників — різні ключі. Реальний старий маршрут є лише у другого. `Тканина та фурнітура` веде до однієї сторінки з двома вкладками; `Операції` — також до однієї сторінки з двома вкладками. `Товари` плануються окремою feature, старого Angular-маршруту немає.

## Розподіл відповідальності

| Область       | Рішення                                                                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Меню          | Статична типізована карта в `apps/admin-react/src/app/router/` або окремому navigation config в app; статус маршруту визначається явною route registry, не фактом наявності тексту в меню. |
| Shell         | `libs/admin/core/shell/src/navigation/` показує групи, доступність, активність і мобільний drawer без знання доменів; `layout/` керує станом мобільного меню.                              |
| Шапка         | `components/admin-top-bar.tsx` зберігає чинні меню й перемикач теми; не додає недіючі іконки зі скриншотів.                                                                                |
| Розширення    | Кожна SDD таблиці додає свій route й одночасно активує відповідний пункт. Пункти без сторінок лишаються недоступними.                                                                      |
| Browser state | Розкриття груп можна зберігати окремим ключем з безпечним fallback; старий Angular-ключ не читати без доведеної сумісності формату.                                                        |

Не дублювати route metadata в двох незалежних списках. Стан disabled відрізняється від активного посилання семантично; клавіатура не повинна потрапляти на неіснуючі адреси. Наявна верхня панель Brevi залишається спільною для всіх майбутніх сторінок.

Карта legacy-пунктів зберігається окремо від перетворення на дієві посилання; shell розділяє контейнер навігації, стан групи й відображення пункту. `/` лишається стартовим маршрутом і не додає пункту «Початок» до меню.

## Ризики та перевірка

Після появи груп перевірити 320/768/1280 px, переповнення довгих назв, скрол бічної панелі, фокус, `aria-current`, контраст обох тем. Референсні скриншоти не доводять наявності пошуку/аватара/API в Brevi. На першому етапі всі 27 старих пунктів недоступні, бо React має тільки `/`; після перенесення чотирьох сторінок і товарів решта недоступних пунктів не повинна відкривати fallback як робочу сторінку.
