# Аудит відповідальностей коду — <назва feature>

- **Feature:** `<точний шлях до feature>`
- **Scope:** `<уся feature або дозволена частина>`
- **Дата:** YYYY-MM-DD

Аудит охоплює наявний код, який feature використовує або змінює, та весь
впроваджений код у дозволених межах. Не розширюйте його на сторонні частини
репозиторію.

## Перед реалізацією

- [ ] Переглянуто фактичні файли, компоненти, модулі й каталоги, їхні імпорти,
      публічні API, тести та використання іншими частинами коду.
- [ ] Визначено власника правил, стану, API, маршрутизації, представлення й
      браузерних адаптерів; перевірено наявні сервіси та компоненти.
- [ ] У `design/frontend.md` записано точні шляхи, поточні змішані
      відповідальності та заплановані межі потрібних змін.

## Після реалізації, до delivery checkpoint

- [ ] Повторно переглянуто весь код feature у scope, включно з повторно
      використаними та новими файлами, а не лише останній `git diff`.
- [ ] Незалежні ролі розділено за наявними межами: окремі функції, компоненти й
      файли або відповідні `components`, `pages`, `hooks`, `state`, `mappers`,
      `data-access` та інші прийняті каталоги й модулі.
- [ ] Після розділення перевірено напрям імпортів, public API, відсутність
      циклів, дублювання стану/правил і перенесення поведінки між шарами.
- [ ] Невеликі цілісні файли залишено разом; кількість рядків сама по собі не є
      причиною створювати файл, компонент, каталог або бібліотеку.
- [ ] Для кожного розділення або рішення залишити код разом записано причину;
      цільові тести й релевантну регресію повторено після структурних змін.
