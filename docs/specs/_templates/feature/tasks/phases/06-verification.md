# Фаза 06 — Планування перевірки та постачання

Створюйте перевірочні `TS-*` лише для окремої приймальної або регресійної
відповідальності. Указуйте точні команди й тестові файли. Плануйте E2E лише для
критичних браузерних сценаріїв і фіксуйте обґрунтовані ручні перевірки для
решти прогалин в інструментах.
Для API feature запишіть результати sync/generate/check, relevant typecheck та
focused tests. Цільові contract scripts запускайте лише після створення їх
`EN-*`; до того фіксуйте прогалину, а не успішну перевірку.
Перед постачанням завершіть `code-audit/audit.md` цієї feature за окремим
модулем `docs/specs/_templates/code-audit/` та повторіть перевірки після
потрібного розділення файлів, компонентів, каталогів або модулів.

**Контрольна точка:** кожен `SC-*` у межах роботи може отримати статус
`verified` через конкретні свідчення та checklist готовності до постачання.
