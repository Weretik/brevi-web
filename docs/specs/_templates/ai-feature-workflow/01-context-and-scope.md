# Контекст і межі

Використовуйте найширші межі, явно дозволені користувачем: уся функціональність,
фаза, вибрані `SC-*` або названі задачі. Не звужуйте доручення на рівні всієї
функціональності до однієї задачі й не розширюйте названу задачу за межі її
залежностей.

Прочитайте застосовні інструкції та документи функціональності, перевірте git
diff, фактичні шляхи вихідного коду, цілі Nx, конфігурації та тести. Задача
готова, коли залежні задачі завершені, шляхи й контрольна точка конкретні,
сценарії однозначні, а рівень тестування доступний або уможливлений `EN-*` у
межах роботи.

Перед змінами перегляньте фактичні файли, компоненти, модулі й каталоги, які
feature змінює або повторно використовує. Зіставте їхні відповідальності з
`design/frontend.md`; прогалини занесіть до
[окремого модуля аудиту коду](../code-audit/README.md); заповнюйте
`<feature>/code-audit/audit.md`.

Зупиняйтеся лише після завершення визначених меж або через конкретне невирішене
продуктове рішення, залежність, потребу в доступі чи руйнівну дію поза межами
дозволу.
