# Перевірка та передавання результату

Запустіть фокусні перевірки, відповідну регресію та доступні цілі
lint/typecheck/build. Вважайте сценарій перевіреним лише після успішного
виконання всіх пов'язаних задач і приймальних свідчень. Для меж усієї
функціональності повторно перегляньте весь наявний і новий код feature,
заповніть `<feature>/code-audit/audit.md` за
[окремим модулем аудиту](../code-audit/README.md)
і checklist готовності до постачання та узгодьте вимоги, контракти, реалізацію
й трасування. Delivery checkpoint не завершено, доки рішення щодо змішаних
відповідальностей і меж файлів, компонентів, каталогів та модулів не виконані й
перевірені. Architecture finding у scope зі статусом `planned`, невизначеним
owner або неузгодженим `deferred` блокує checkpoint.

Після структурних змін перевірте project graph/module-boundary lint, усі
публічні entry points, відсутність заборонених imports/tools, typecheck source і
tests, focused/regression tests та build відповідного application. Перевірте,
що порожні, дубльовані й мертві каталоги або aliases не залишилися.

У звіті наведіть завершені `SC-*`/`TS-*`/`EN-*`, спостережувану поведінку,
змінені файли, свідчення TDD, неперевірені елементи та залишкові ризики.
Зберігайте сторонні зміни робочого дерева. Продовжуйте роботу через межі задач і
фаз, доки дозволені межі не завершені або не виник конкретний блокер.
