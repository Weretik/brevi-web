# Контекст і межі роботи

## Визнач поточну фазу

- Виконуй **лише** файл фази з вказаним номером у `<feature>/tasks/`, наприклад
  `tasks/00-specify-plan.md`.
- Якщо користувач дав шлях одразу до файла фази, номер фази використовуй для
  перевірки відповідності. Якщо вони не збігаються, зупинись і попроси
  уточнення.
- Наступні фази дозволено читати лише для розуміння залежностей. Не змінюй їхні
  файли, код або перевірки без явної команди користувача.

## Що прочитати до змін

1. Знайди `AGENTS.md` від кореня репозиторію до папки файлу, який буде змінено,
   і виконай усі застосовні інструкції.
2. Прочитай повністю поточний файл фази, `<feature>/tasks/README.md` і
   `<feature>/spec.md`.
3. Прочитай документи, файли й контракти, на які прямо посилаються задачі фази.
   Для фази `00` це щонайменше `plan.md`, `research.md` (якщо є),
   `data-model.md` (якщо є), `contracts/api-contract.md` (якщо є) та
   `quickstart.md`.
4. Перевір попередні фази: їхні задачі мають бути завершені, а checkpoint — не
   містити незакритого blocker.
5. Переглянь релевантний наявний код, тести й конфігурацію лише настільки,
   наскільки це потрібно для поточної фази.

## Коли зупинитися

Не вигадуй endpoint, DTO-поля, ролі, UX-поведінку, шлях файлу чи вимоги, яких
немає у специфікації або чинному коді. Якщо бракує необхідної інформації або
незавершена попередня фаза, зафіксуй blocker у відповідному feature-документі,
якщо цього вимагає фаза, коротко поясни його користувачу та чекай рішення.

Не роби попутного рефакторингу, оновлення залежностей або виправлень поза scope
поточної фази.
