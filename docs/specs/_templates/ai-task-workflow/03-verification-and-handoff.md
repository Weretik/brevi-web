# Перевірка і передача фази

## Перевір результат

1. Запусти всі перевірки, прямо задані у фазі, `quickstart.md`, `AGENTS.md` і
   застосовних testing-правилах, але лише коли вони релевантні зміненим файлам.
2. Спершу виконай найбільш вузьку перевірку; lint, unit/integration tests і
   build виконай відповідно до ризику та правил репозиторію.
3. Якщо команда не запускається або падає, зафіксуй точну команду, результат,
   failure point і чи є проблема наслідком поточної зміни або вже існувала.
4. Перевір `git diff` для власних змін: вони мають відповідати лише поточній
   фазі. Не змінюй і не відкидай сторонні зміни робочої директорії.

## Умова завершення

Фаза завершена тільки коли:

- усі її checkbox-задачі позначено `[x]`;
- checkpoint виконаний, а blockers відсутні або явно потребують рішення
  користувача;
- фактичні зміни, контракти й документація не суперечать одне одному;
- результати перевірок або причина їх невиконання записані в `quickstart.md`,
  коли це застосовно.

## Формат підсумкового звіту

1. **Виконано** — ID завершених задач і короткий результат.
2. **Змінені файли** — лише файли поточної фази.
3. **Перевірки** — команди, результати та ручні сценарії.
4. **Не перевірено / блокери** — точна причина; якщо таких немає, напиши це.
5. **Ризики / ручна перевірка** — лише реальні залишкові пункти.
6. **Статус** — `Фаза <номер> завершена. Очікую команду «Переходь до фази <наступний номер>».`

Після звіту не починай наступну фазу й не виконуй нових змін, доки користувач
явно не назве її номер.
