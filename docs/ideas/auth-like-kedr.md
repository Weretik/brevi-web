## 2. Что сделать

Делать после шага 0 (адрес `api.brevi.com.ua`) и вместе с шагом 2 бэкенда из главного документа.

### Админка

1. **Адрес API.** В `environment.prod.ts` заменить `*.run.app` на `https://api.brevi.com.ua`.
2. **Cookie-сессия вместо токена.** Вход `POST /api/auth/cookie/login`, выход `POST /api/auth/cookie/logout`, текущий пользователь `GET /api/auth/session/me`. Все запросы с `withCredentials: true`. Токен в JavaScript больше не хранится: убрать `session-state.ts`, заголовок `Authorization` и refresh-перехватчик.
3. **CSRF.** Для `POST`, `PUT`, `PATCH`, `DELETE` читать cookie `brevi.csrf` и отправлять в заголовке `X-CSRF-Token`.
4. **Страница входа** `/login`: почта и пароль, понятные ошибки (неверные данные, учётная запись заблокирована на 15 минут, слишком много попыток). После входа вернуть на страницу, откуда пришёл.
5. **Защита маршрутов.** При старте запросить `me`. Нет сессии → `/login`. Ответ `401` на любой запрос → сбросить состояние и перейти на `/login`.
6. **«Нет доступа».** Ответ `403` → страница или сообщение «Нет доступа» вместо общей ошибки.
7. **Меню по ролям.** Из `me` взять роли; прятать пункты, на которые нет прав (например, «Пользователи» только для Admin). Проверку Sewing `sewing-access` перевести на те же роли.
8. **Страница «Пользователи»** (только Admin): список сотрудников, создание Admin или Manager (почта, имя, пароль), смена роли, блокировка и разблокировка, новый пароль. Свою учётную запись заблокировать или понизить нельзя.
9. **Контракт.** После изменений в BreviERP обновить OpenAPI-снимок (`npm run contracts:check`) и типы.
10. Переименовать `kedr.csrf` в `brevi.csrf` вместе с бэкендом.

### Витрина

Пока витрина не обращается к API, вход ей не нужен. Когда появится каталог из API, использовать только публичные endpoints для чтения. Если позже будет личный кабинет, вход через ту же cookie на `api.brevi.com.ua`, как в Kedr.

## 3. Риски

- Выкатывать вместе с бэкендом: после закрытия админских API старая админка без входа перестанет работать.
- Локальная админка (`localhost`) с продакшен-API cookie-вход не получит. Для разработки нужен локальный BreviERP.
