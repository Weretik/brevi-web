# Технології та прямі npm-залежності Brevi Web

**Перевірено:** 2026-10-15. **Джерела версій:** кореневі `package.json` (оголошено) і `package-lock.json` (розв’язано). Реєстр містить усі 31 прямі runtime та 86 прямі development записи. Він не перераховує транзитивне дерево. Статус «інструмент» означає призначення пакета, а не доказ використання кожного плагіна в поточному target. Позначки «перевірити» залишаються чесними відкритими питаннями.

## Архітектурні рішення й правила оновлення

- Angular Storefront: SSR/гідратація, локалізація й runtime описані у [Storefront runtime](storefront/runtime.md); HTTP pipeline і відсутність поточного API consumer — у [Storefront API](api/storefront.md). При додаванні API перевір server/browser поведінку та контракт.
- React Admin: MUI/Emotion, routing і state мають власні межі в [Admin architecture](admin/README.md). Axios/RTK Query описані в [API architecture](api/README.md) як цільовий transport; зіставляй цей документ з кодом перед зміною залежностей.
- OpenAPI types генеруються через `contracts:generate`, джерело й перевірки описані в [contract workflow](api/contract-workflow.md). Не редагуй generated типи вручну.
- Після додавання, видалення чи оновлення прямого пакета синхронізуй manifest/lockfile штатним npm workflow, звір реальне використання і онови цей реєстр та відповідні app-документи.
- Для пакетів із позначкою «перевірити» не припускай, що вони мертві. Спочатку переглянь imports, CSS, config, scripts і Nx inferred targets; результат фіксуй у зміні, що стосується пакета.
